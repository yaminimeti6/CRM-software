## Connection and worker behavior

OAuth requests ads_read only. Random ten-minute state is one-use, HttpOnly-cookie-bound and tied to organization, authenticated actor, verified Supabase session ID and connection generation. Denied consent does not create a verified connection. The callback verifies granted permission and performs real ad-account discovery before storing a verified connection. Tokens use AES-256-GCM with organization-bound authenticated data and a persistent server-only key. Browser responses contain neither tokens nor app secrets. Reconnect/disconnect invalidates in-flight generations and preserves published snapshots.

Admin account selection performs a fresh provider account read, validates the discovered connection generation, and queues a job. Interval is 15?1440 minutes (default 60); overlap is 1?90 account-local days (default 30), including the provisional current day. The separate worker polls every five seconds, schedules due accounts persistently and processes one bounded Graph page at a time. Partial unique jobs, SKIP LOCKED leases, checkpoint fencing, idempotent page upserts and transactional publication prevent concurrent duplicates. A crashed lease can be reclaimed. Rate limits/transient errors back off, honor bounded Retry-After and stop after bounded retries. Token errors require reconnect. No partial job replaces the previous published snapshot. A restarted worker resumes durable work; stopping the web app does not run sync in an HTTP request.

Campaign/ad-set/ad/creative identity is organization + provider + account + external ID, never name. Provider renames refresh provider-owned references without overwriting manual references or historical lead attribution. An Admin can explicitly review a same-kind manual-to-Meta link; it is revision-checked, audited and prospective only. Neither matching names nor new links silently backfill old leads.

## Accounting and privacy policy

Canonical facts are one ad/day in one account/currency using numeric(20,6), never JavaScript floating-point money. Shared creatives cannot multiply spend. Provider lead actions use exactly action_type=lead; related action types remain separate and are not summed as interchangeable leads. Missing actions/rows remain unknown, not zero. Explicit zero is retained. Reports preserve account currency/timezone and unified attribution settings plus available ad-set attribution_spec. Meta dates use account local days; CRM received-cohort dates use Asia/Kolkata.

Partial-capture CRM CPL = canonical eligible group spend / distinct eligible received-cohort CRM leads. Confirmation cost = the same spend / distinct cohort leads with an observed CRM confirmation by report as-of. Cancellation/reconfirmation does not multiply this denominator; historical imported Confirm alone is not an observed confirmation. This is an acquired-lead cohort measure, not confirmation events in the period. Manual/unmapped leads are shown as coverage counts without assigning them spend. Configured attribution is frozen at submission/import; raw claims cannot make a lead eligible.

Costs are N/A for zero denominators, incomplete/outside published daily coverage, incompatible non-IST daily windows, lead subset filters that cannot partition spend, and current creative allocation (historical creative version is not proven). Current creative grouping is explicitly labelled, not visual deduplication. Creative Analysts retain existing small-group protection/rounded counts; costs are N/A rather than dividing by rounded counts. No customer PII, lead IDs or exports are introduced for Analysts. Connection changes, role changes and deactivation are rechecked server-side; report UI clears revoked access. Step 6B is pending, so even eligible costs are labelled partial-capture and must not be represented as reliable overall campaign CPL.
